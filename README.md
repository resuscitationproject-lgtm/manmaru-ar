# まんまる文化祭 ARスタンプラリー — Phase 1

自治会・地域イベントへ横展開できる標準品を想定した、7ARポイントの静的Webアプリです。子どもたちが描いた原画やマスコットの図柄をカメラで認識し、対応する3Dモデルを表示します。「スタンプを貯める」を押すとスタンプを端末の `localStorage` に保存します。

## Phase 1でできること

- iPhone Safari / Android Chromeからカメラを起動
- MindAR + A-Frameによる画像ターゲット認識
- 子どもたちの原画6枚と二瀬窯業様の「カメ会長」図柄1枚を、対応する3Dモデルへ番号で紐付け
- 認識した原画・マスコット図柄に対応するGLBモデルをAR表示
- 認識中だけスタンプボタンを表示
- イベントID・ポイントID単位でスタンプを端末保存
- 端末内のスタンプ記録をリセット
- `event-config.json` と素材の差し替えによるイベント展開
- GitHub Pagesのサブディレクトリ配信

カメラ画像はブラウザ内で処理し、サーバーへ送信しません。スタンプは端末・ブラウザ単位の保存です。ブラウザの履歴やサイトデータを消すと失われ、別端末には引き継がれません。

トップ画面の「スタンプをリセット」は、このアプリのイベントIDに紐づくスタンプ記録だけを削除します。ブラウザ全体のキャッシュ、履歴、ほかのサイトのデータには影響しません。

## ファイル構成

```text
manmaru-ar-stamp-rally/
├── index.html
├── complete.html             # 保存済みスタンプから再表示できる達成画面
├── event-config.json          # イベント名、ARポイント、達成条件
├── styles.css
├── js/
│   ├── app.js                 # AR画面とイベント進行
│   ├── ar-display.js          # 描画サイズとモデル表示状態の同期
│   └── stamp-store.js         # localStorage保存（複数ポイント対応）
├── assets/
│   ├── targets.mind           # 7原画＋カメ会長POP補助1枚の認識データ
│   ├── targets/               # 01〜07の原画・マスコット図柄とPOP補助画像
│   ├── models/                # ターゲットと同番号の01〜07 GLBモデル
│   └── main-visual-2026.jpg   # トップ画面のメイン画像
└── tests/
```

`targets.mind` は、会場で認識させる7枚の画像を `01` から `07` の順番で投入し、最後にカメ会長POP補助画像を加えてコンパイルします。順番を変えると画像と3Dモデルの対応がずれるため、ファイル名と投入順を揃えてください。二瀬窯業は6番目、本キャラは7番目の `07_blue_book.jpeg` です。本キャラの元素材名は `06_book.jpeg` / `06_blue_book.blend` ですが、アプリ内では既存番号と重複しない `07` を使います。

## ローカルで確認する

ファイルを直接開く `file://` ではカメラや設定ファイルの読み込みが動きません。フォルダ内でローカルWebサーバーを起動します。

```bash
cd manmaru-ar
npx serve .
```

PCでは表示確認ができます。スマートフォン実機でカメラを使うときは、GitHub PagesなどのHTTPS環境へ公開してください。

保存処理のテストは次で実行できます。

```bash
npm test
```

## MindAR Image Target Compilerで `targets.mind` を作る

1. 会場に掲示する `01_pencil.jpg`〜`05_hero_dog.jpg`、`06_kame_kaicho.png`、`07_blue_book.jpeg` を用意します。図柄は実際に提示する状態と同じにしてください。
2. [MindAR Image Targets Compiler](https://hiukim.github.io/mind-ar-js-doc/tools/compile/) をPCブラウザで開きます。
3. 7枚を `01`、`02`、`03`、`04`、`05`、`06`、`07` の順に投入し、最後に補助画像 `06_kame_kaicho_pop.png` を追加して `Start` を押します。画像データは8点ですが、スタンプは7点です。
4. 特徴点の表示を確認します。点が少ない場合や一部に偏る場合は、画像を調整して再度コンパイルします。
5. `Download` を押して `targets.mind` を保存します。
6. ダウンロードしたファイルで `assets/targets.mind` を上書きします。
7. コンパイル元の画像を印刷し、照明・距離・角度を変えて実機テストします。

Compilerへ投入した順番が `event-config.json` の `targetIndex`（0始まり）に対応します。`01_pencil.jpg` は `targetIndex: 0`、`06_kame_kaicho.png` は `targetIndex: 5`、`07_blue_book.jpeg` は `targetIndex: 6`、カメ会長POP補助画像は `targetIndex: 7` です。認識画像8点を7スタンプへ関連付けています。

## 原画と3Dモデルを差し替える

1. 原画を `assets/targets/`、対応するGLBを `assets/models/` に同じ番号で配置します。
2. 原画を番号順にCompilerへ投入し、`assets/targets.mind` を作り直します。
3. `event-config.json` の `sourceImage`、`modelFile`、`name`、各メッセージを変更します。
4. 実機を見ながら `modelScale`、`modelPosition`、`modelRotation` を調整します。

子どもたちの6つのGLBは、モデル内部に全体倍率用の親要素を追加し、元データの3倍に加工済みです。ブラウザ側で追加の3倍拡大は行っていません。元のGLBへ戻して再加工する場合は `node scripts/scale-glb-roots.mjs 3 assets/models/07_blue_book.glb` のように実行します（同じファイルへの二重適用は防止されます）。本のBlenderデータはキャラクター部分だけをGLB化し、撮影用の床・カメラ・照明は含めていません。

### 二瀬窯業様「カメ会長」への差し替え（2026-10-13）

二瀬窯業の6番目のポイントは、メモスタンドの集合写真・3Dから、添付のカメ会長図柄と `kame_kaicho.blend` の3Dへ差し替えました。取得済みスタンプを引き継ぐため、このポイントの内部IDは従来の `futase-memo-stands` のまま維持しています。旧メモスタンドの素材は保管用に残していますが、アプリからは使用しません。

認識画像は `assets/targets/06_kame_kaicho.png`。旧メモスタンドの写真では認識しません。スタンドPOPにはこの画像を縦横比・図柄を変えずに配置してください。社名・QR・説明文は画像の外に置き、絵を切り抜いたり文字を重ねたりしないでください。POP完成後、実際の印刷物で距離・角度・照明を変えて試してください。

カメ会長GLBは67部品を含み、Blenderの曲線・胸文字もメッシュに変換して出力しています。撮影用床・ライト・カメラ・参考画像は除外。全体を1つの親要素で均等に拡縮し、モデル高さを約0.9へ合わせています。体形・色・部品の相対位置を変える加工は行っていません。

取得直後の吹き出しと取得案内は「素敵なメモスタンドを作りましょう！」。取得済みの端末でも「3Dをもう一度表示」で同じ吹き出しを確認できます。`points[].acquiredMessage` を設定したポイントだけがこの動作を使い、他のキャラは従来どおりです。

モデルには環境光・方向光と半透明の影を付けています。現在は設定した位置・向き・縮尺で表示します（自動浮上・回転のアニメーションはありません）。

iPhoneでのメモリ使用量を抑えるため、7つの3Dモデルは一括で先読みせず、認識したポイントのモデルだけを読み込みます。モデルや `targets.mind` を更新した際は、`event-config.json` の `assetVersion` も変更して端末の古いキャッシュを回避します。

### カメ会長の現場POP認識を補強（2026-11-09）

録画では、現場の印刷物を映してから画像認識が成立するまで待ち時間があり、3D読み込みより前の段階が主な問題でした。キャラ単体の原画（index5）は維持し、現場POPから作った補助認識データを末尾に追加しています（現在はindex7）。補助画像は読み取り専用で、印刷用の新デザインではありません。既存のPOPを貼り替える必要はありません。

補助データの元は印刷物のキャラ・赤い社名コメント部分のみです。録画全体・人物・ガラス面の周辺風景・ナンバープレートは公開しません。背景の透け文字も認識用に抑制しています。現在使う7点の認識データは内容を維持し、補助画像を最後に配置しています。

`points[].targetVariants` で同じスタンプに複数の画像を関連付けます。原画とPOPの両方が `futase-memo-stands` の1スタンプです。7ポイントの順序・保存ID・カメ会長の1.7倍表示（modelScale=0.612）・GLBの形状は変えていません。補助画像は原画座標に位置合わせし、画像の下余白による中心位置の差だけを補正します。

同じGLBを使う原画と補助画像は、最初に読み込んだ形状・材質を共有し、画像が切り替わるたびにダウンロード・解析・GPU形状を二重に持たないようにしています。現在の静的モデル向けで、骨・アニメーション付きモデルの複製は別途対応が必要です。認識ガイドは、画像を大きく映してスマホを少し止める案内に変更しています。

PCでの録画静止画3場面の同条件比較では、従来は1/3、新しい補助データ併用では2/3を認識。従来8秒以内に認識できなかった1場面を約0.6秒で認識しました。一方、ぼけの強い場面は認識できず、実機での再確認が必要です。全距離・全角度での認識や実機で同じ時間になることを保証するものではありません。

### 7ポイント構成へ更新（2026-11-12）

依頼により、ていたん画像と対応する人物キャラの3Dを公開アプリから削除しました。認識データからも該当1点を取り除き、カメ会長POP補助画像をindex8からindex7へ移動しています。残る7原画とPOP補助画像のコンパイル済み内容は維持しています。

イベントIDと7ポイントの保存IDは維持し、コンプリート条件を7個に更新しました。既存のスタンプはリセット不要です。以前の8個目の記録が端末に残っていても、現在の7ポイントだけを集計するため、表示は7/7までです。

### 表示安定性の修正（2026-10-10）

AR領域を隠したまま初期化すると描画バッファが0×0になるため、画面表示・AR準備完了・領域サイズ変更時にrendererのサイズを同期します。カメラ投影・動画の切り取りはMindAR 1.2.5の調整を維持します。ターゲット親要素のvisibleや行列はMindARだけが管理し、アプリは子のモデルだけを表示・非表示にします。追跡ロスト後に読込完了しても親を強制表示しません。

バックグラウンド移行でカメラを停止した場合、短時間の移行でもAR画面への復帰時にページを再初期化します。もう一度「カメラを起動する」を押してください。スタンプ記録は維持されます。通常のカメラ画面の閉じる→再起動ではモデルを再利用します。

## `event-config.json` の考え方

- `event.id`: localStorageの保存領域を分ける一意なID。年度やイベントが変わる場合は必ず変更します。
- `event.heroImage`: トップ画面に表示するイベントのメイン画像。ARキャラクター画像とは独立して差し替えられます。
- `ar.targetFile`: Compilerで作った `.mind` ファイル。
- `points[]`: キャラクターごとの原画、3Dモデル、表示サイズ、メッセージをまとめた配列。
- `targetIndex`: `.mind` 内の画像順。先頭は `0`。
- `completion.requiredStampCount`: コンプリートに必要な数。現在は `7`。既存7点の取得記録を維持します。
- `completion.message`: 全7個の取得後に表示する案内。受付でこの画面を見せ、先着順で景品を受け取ることを説明します。

アプリは `points` をループしてARエンティティを生成します。将来ルーレットを追加するときは、保存済みポイント数が `requiredStampCount` に達した後のコンプリート処理から遷移できます。

## 達成画面の再表示

7個目を取得すると、保存完了後すぐにカメラを停止して、同じイベントディレクトリ内の `complete.html` へ移動します。達成画面には受付・先着順の景品案内と取得したスタンプ一覧を表示します。閉じるボタンで消すモーダルではなく、再読み込みやブラウザの開き直しでも、同じ端末・ブラウザの保存記録から再表示します。

すでに7個取得済みの場合は、`index.html` またはイベントの通常URLを開いても達成画面へ自動的に移動します。未達成の端末で `complete.html` を直接開いた場合は通常のアプリへ戻ります。達成画面はカメラ・MindAR・A-Frameを使いません。素材やスタンプ記録を変更する必要はありません。

リセットは達成画面下の「スタンプの管理」から行えます。確認ダイアログで承認した場合だけ保存記録を消して通常画面へ戻ります。端末・ブラウザを変えた場合やサイトデータを削除した場合は、達成記録を引き継げません。これは従来のlocalStorage保存と同じ制約で、景品の受け渡し済み管理は行いません。

## GitHub Pagesへ公開する

1. このフォルダをGitHubリポジトリへ置きます。複数イベントを1リポジトリで管理する場合は、イベントごとにディレクトリを分けます。

   ```text
   repository-root/
   ├── manmaru-2026/
   ├── kurosaki-2026/
   └── index.html
   ```

2. GitHubのリポジトリで **Settings → Pages** を開きます。
3. **Build and deployment** で **Deploy from a branch** を選び、公開ブランチと `/ (root)` を指定します。
4. 公開完了後、スマートフォンでHTTPSのURLを開きます。

想定URLは次の形です。

```text
現在の公開URL: https://manmaru-ar.kitakyushu-itclub.org/
GitHub Pages URL（独自ドメインへ転送）: https://resuscitationproject-lgtm.github.io/manmaru-ar/
将来: https://ar.kitakyushu-itclub.org/manmaru-2026/
```

`ar.kitakyushu-itclub.org` をリポジトリのカスタムドメインに設定すれば、イベントごとのDNS設定は不要です。各イベントは同じドメイン配下のディレクトリとして運用します。

## QRコード

GitHub Pagesで確定したイベントURLをQRコード化します。QRコードには必ず末尾の `/` まで含む本番HTTPS URLを使ってください。印刷前に、iPhoneとAndroidの標準カメラから読み取り、目的のページが直接開くことを確認します。

## 実機テスト手順

1. iPhone SafariとAndroid ChromeでQRコードを読みます。
2. 「カメラを起動する」を押し、カメラ利用を許可します。
3. `assets/targets/` のターゲット画像7枚を別画面に表示するか、会場用サイズで印刷します。カメ会長は現場POPでも確認します。
4. ターゲット全体を明るい場所で枠内に映します。
5. 正しいキャラクター名とスタンプボタンが現れることを確認します。
6. 原画と同番号の3Dモデルが表示され、スタンプ取得後も表示されることを確認します。
7. 7ポイントすべてで、モデルの向き・大きさ・明るさ・追従を確認します。
8. ページを再読み込みし、獲得済みポイントでは3Dモデルが再表示されることを確認します。
9. 低照度、逆光、斜め、距離、混雑時の回線で試します。
10. SafariのプライベートブラウズやChromeのシークレットモードは保存が消えやすいため、本番案内では通常モードを推奨します。
11. カメラを閉じて再起動、ブラウザを閉じて開く、別アプリへ移動して戻る（1秒未満と数秒の両方）を各3回試します。
12. ターゲットを外す→再度映す操作を10回繰り返し、3Dとスタンプボタンが復帰することを確認します。画面回転・アドレスバー伸縮時も確認します。

## イベント終了後の運用

推奨は、即時削除ではなく「公開停止 → 保管 → 削除」です。

1. 終了時刻後、イベントURLの `index.html` を終了案内ページへ置き換えて公開停止します。
2. 設定、ターゲット画像、`targets.mind`、キャラクター素材、確定URLを非公開保管します。
3. 30〜90日後、問い合わせがなければ公開ディレクトリを削除します。
4. 翌年再利用する場合は別の `event.id` とディレクトリ名にして複製します。前年の端末データが混ざるのを防げます。

個人情報を収集しないPhase 1でも、素材の利用許諾と掲載期間は主催者・制作者間で確認してください。

## 現時点の制約

- スタンプは端末内保存のみで、不正防止や端末間同期はありません。
- 3Dモデルの見え方は各GLBの原点・向き・マテリアルに影響されるため、実機でポイントごとの微調整が必要です。
- ライブラリはCDNから読み込むため、初回起動時はインターネット接続が必要です。
- iOSではユーザー操作からカメラを開始する必要があるため、起動ボタンを設けています。

MindARの基本構成とCompiler手順は[公式ドキュメント](https://hiukim.github.io/mind-ar-js-doc/)を参照してください。
